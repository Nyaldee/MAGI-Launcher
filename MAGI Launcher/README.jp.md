*[Read in English](README.md) · [Lire en français](README.fr.md) · [阅读中文版](README.zh-CN.md)*

Windows と Linux 向けの、高速で多機能な、キーボードだけで操作するアプリケーションランチャーです。グローバルホットキーを押し、数文字入力して Enter。アプリ、フォルダー、ショートカットを起動するほか、電卓や 16 進カラーのプレビューにもなります。開いているウィンドウの切り替え、手軽なタイマー、付箋メモ、起動し続けたいものの自動再起動、ごみ箱の中身の閲覧と空にする操作、名前での絵文字検索、メディア再生の操作、RAM 上だけのクリップボード履歴（任意）、そして Windows 自身が取り出しを拒むことのある USB ドライブの取り出しまでこなし、100 以上のカラーテーマを同梱しています。インストーラー不要の小さく軽い実行ファイルで、自分のショートカット一覧以外に設定するものはありません。Linux での違いは [Linux](#linux) をご覧ください。

## 機能

- どこからでもランチャーを呼び出し／閉じるグローバルホットキー（既定は `Ctrl+Space`、変更可能）
- アプリ、フォルダー、ショートカットの一覧をあいまい検索
- 実行ファイルの隣に置く `shortcuts/` フォルダー — 任意のファイル（`.lnk`、`.bat`、`.cmd`、`.vbs` など何でも）を入れると、自動的に起動できる項目になり、`apps.json` の項目の後に表示されます
- 電卓（`2*(3+4)` → `= 14`、Enter で結果をコピー）
- 16 進カラーのプレビュー（`#3a8ea0` で一覧がその色で塗られ、Enter で 16 進コードをコピー）
- Window Switcher — 開いているウィンドウをあいまい検索してすぐに切り替え、その場で閉じたり強制終了したりもできます
- 期間を解釈するタイマー（`5m`、`90s`、`1h`）と、時間になると始まる DVD ロゴ風スクリーンセーバーのイースターエッグ
- Sticky Notes — 件数無制限で検索できる短いテキストメモの一覧。その場でコピーや削除ができます
- Auto-restart — 起動し続けたい対象を選ぶと、そのプロセスが消えたとき（クラッシュでも手動で閉じた場合でも）、数秒以内に自動で再起動します
- Auto-kill — Auto-restart の逆：終了させておきたい対象を選ぶと、数秒ごとに見つけ次第終了させます。既定では無効で、有効にするたびに 10 秒の猶予があり、「MAGI 自身は決して終了させない」という絶対のルールがあります
- ごみ箱の項目数とサイズをリアルタイムに表示し、中身をランチャーから直接閲覧 — 項目名のコピーや個別の削除、キー 1 つで空にすることもできます
- 絵文字ピッカー — Unicode の公式な絵文字名をあいまい検索し、カラーで表示。`Enter` で絵文字そのものをコピー
- Copy History — 任意の、RAM 上だけのコピー履歴（テキストのみ）。ランチャーから閲覧して再コピーでき、ディスクには一切書き込まれません
- Eject — 接続中の USB ドライブを検索できる一覧。`Enter` でその場で取り出し（使用中なら `Shift+Delete` で強制）。Windows 自身の「取り出し」が表示されない、またはグレーアウトしている場合でも動作します
- 物理的なメディアキーボードなしでメディアキーを操作（再生／一時停止、次／前のトラック、音量）
- 100 以上の組み込みカラーテーマを、ランチャーから即座にプレビューしながら切り替え可能。再起動は不要です
- ポップアップと枠の大きさをキーボードでリアルタイムに変更（`Ctrl+1`〜`Ctrl+0` ／ `Ctrl+-`・`Ctrl+=`）、すぐに保存されます
- 通知領域アイコン付きの単一インスタンスで動作（ホットキーの切り替え／Auto-restart の切り替え／Auto-kill の切り替え／Copy History の切り替え／Website／終了）
- どのアプリにも一致しないものは「ファイル名を指定して実行」（Win+R）と同じ動作になります

## キーボードショートカット

| キー | 動作 |
|---|---|
| グローバルホットキー（既定は `Ctrl+Space`） | ランチャーの表示／非表示 |
| 入力 | 一覧をリアルタイムにあいまい検索で絞り込み |
| `↑` / `↓` または `Ctrl+W` / `Ctrl+S` | 選択を上／下へ移動 |
| `←` / `→` または `Ctrl+A` / `Ctrl+D` | 1 ページ（10 項目）戻る／進む |
| `Enter` | 選択した項目を起動 — *（ごみ箱のメイン項目）* 空にする代わりに中身を閲覧 — *（ごみ箱の閲覧画面）* 選択中の項目の完全な名前（拡張子付き）をクリップボードにコピーしてランチャーを閉じる — *（Copy History）* 選択中の項目を再コピーしてランチャーを閉じる。履歴には追加し直しません — *（Eject）* 何も開いていなければ選択中のドライブを取り出し、使用中なら何もしない（強制は `Shift+Delete`）。どちらの場合もランチャーは開いたままなので、続けて複数取り出せます |
| `Shift+Enter` | 起動する代わりに、選択した項目をファイルマネージャーで表示 — *（ごみ箱のメイン項目）* ごみ箱を空にする（ランチャーは開いたまま） — *（Sticky Notes）* コピーする代わりに `notes.json` を既定のエディターで開く |
| `Tab` | Window Switcher へ移動 — メイン一覧に限らず、ランチャーのどこからでも同じように動作 |
| `Escape` | どのモードからでもメイン一覧に戻る — すでにメイン一覧ならランチャーを閉じる。タイマーの DVD 風スクリーンセーバー中は、閉じずに跳ね回りを止めてメイン一覧に戻る |
| `Delete` | *（Window Switcher）* 選択中のウィンドウを穏やかに閉じる（`WM_CLOSE`、× ボタンを押すのと同じ） — *（Sticky Notes のピッカー内）* 選択中のメモを削除 — *（メイン一覧の「Note」項目上）* ピッカーを開かずに最新のメモを直接削除 — *（Auto-restart）* 選択中の対象の監視をやめる — *（Copy History）* 選択中の項目を削除 — *（ごみ箱のメイン項目）* ごみ箱全体を空にする（ランチャーは開いたまま） — *（ごみ箱の閲覧画面）* 選択中の項目だけを完全に削除 — *（タイマー、作動中または期間の入力中）* カウントダウンを取り消す |
| `Shift+Delete` | *（Window Switcher）* `Delete` に応答しなくなったウィンドウのプロセスを強制終了 — *（Sticky Notes）* すべてのメモを削除 — *（Auto-restart）* すべての対象の監視をやめる — *（Auto-kill）* 終了対象をすべて消去 — *（Copy History）* 履歴をすべて消去 — *（ごみ箱の閲覧画面）* ごみ箱全体を空にする（ランチャーは開いたまま） — *（Eject）* 使用中でも選択中のドライブを強制的に取り出す。ここでは `Delete` だけでは何もしません |
| `Ctrl+1`〜`Ctrl+9` / `Ctrl+0` | ポップアップを画面幅の 10%〜90% ／ 100% にリアルタイムで変更し、すぐに `state.json` に保存。AZERTY のように数字に `Shift` が必要な配列では、`Shift` も一緒に押してください |
| `Ctrl+-` / `Ctrl+=` | 枠を 1px 細く／太くする。リアルタイムで、すぐに保存。`Ctrl++` でも動作します |
| 検索欄が空のときの `Backspace` | Window Switcher ／テーマピッカー／タイマー／ Sticky Notes ／ Auto-restart ／ Auto-kill ／ごみ箱の閲覧画面／絵文字ピッカー／ Copy History ／ Eject から抜ける |
| 通知領域アイコンを左クリック | ランチャーの表示／非表示 |
| 通知領域アイコンを右クリック | ホットキーの切り替え／ Auto-restart の切り替え／ Auto-kill の切り替え／ Copy History の切り替え／ Website ／終了のメニュー |

検索欄は常にキーボードフォーカスを保持します。上のキーはすべてそこで直接受け取られるので、入力を続けるために別の場所をクリックしたりタブで移動したりする必要はありません。マウスはランチャーのウィンドウ内ではまったく効きません（クリック、ホバー、カーソルの変化もなし）。反応するのは通知領域アイコンだけです。`Alt+F4` でランチャーのプロセスが終了することはなく、`Escape` と同じくポップアップを隠すだけです。ランチャーが終了するのは、通知領域メニューの「Quit」からだけです。

## 検索モード

検索欄に入力した内容は、次の順に解釈されます：

1. **16 進カラー**（`#fff` や `#3a8ea0`） — 一覧全体をその色で塗ってリアルタイムにプレビューします。`Enter` で 16 進コードをクリップボードにコピー。
2. **数式**（`2+2`、`100/3` のように演算子を含む必要があります） — `= <結果>` を表示し、`Enter` で結果をコピー。数値と算術演算子だけに限定した、手書きの小さな再帰下降パーサーで評価されます。名前を参照したり、何かを呼び出したり、式の外に出たりするものは一切実行されません。
3. **アプリ名** — あいまい一致：検索語の各単語が、順不同ですべて一致する必要があります。その文字が名前の中に順番どおり近い位置に現れるか、名前の各単語の頭文字（3 文字から）である必要があるので、`vsc` で「Visual Studio Code」が見つかります。1 文字の英字や数字は、名前の先頭、次に各単語の先頭だけを見ます。結果の順位は、完全な前方一致、単純な部分一致、あいまい一致（より詰まった一致ほど上位）の順です。同じ段階で並んだ場合は `apps.json` の項目の順番を保つので、同じくらい良い一致の中では、`apps.json` で上にあるものが先に表示されます。使用履歴や頻度による並べ替えは一切ありません。MAGI は以前に何を起動したかを記憶せず、`apps.json` での位置だけが、どれほど頻繁に（あるいは最近）選んだかに関係なく、常に同じ決め手になります。
4. **それ以外** — 何も一致しなければ、`Enter` で入力した文字列を Windows の「ファイル名を指定して実行」（`Win+R`）のように、`apps.json` の項目と同じ方法で実行します。打ち間違いでも、たまたまコマンド名になっていれば `Enter` で実行されます。メールアドレスの形をした入力（`someone@example.com`）は、存在しないファイルパスとして失敗する代わりに `mailto:` として開かれます。

## Window Switcher

ランチャーのどこからでも `Tab` を押すと、開いているすべてのトップレベルウィンドウが一覧表示されます（タイトルは、アプリと同じあいまい検索で絞り込めます）：

- `Enter` で選択中のウィンドウをアクティブにする
- `Delete` で穏やかに閉じ（`WM_CLOSE`、× を押すのと同じ）、次のウィンドウのためにスイッチャーにとどまる
- `Shift+Delete` で、`Delete` に応答しなくなったウィンドウのプロセスを強制終了（`TerminateProcess`）
- `Escape` で、どのウィンドウにも触れずにスイッチャーからメイン一覧に戻る

`Shift+Delete` は、あえて `Delete` による通常の終了と修飾キー 1 つ分しか違わないようにしています。多くのウィンドウ — たとえばエクスプローラーのフォルダーウィンドウはすべて — デスクトップやタスクバーと同じプロセスで動いています（「フォルダーウィンドウを別のプロセスで開く」が有効でない限り）。そのため、そのうちの 1 つに `TerminateProcess` を使うと、選択中のウィンドウだけでなく `explorer.exe` 全体が落ちます。`Delete` がどうしても効かないときだけ使ってください。

## Timer

`"magi:timer"` 項目（下記参照）を追加すると使えるようになります。タイマーの中にいる間、検索欄のプレースホルダーは `Type a duration (5m, 90s, 1h...)` に変わります。期間（`5m`、`90s`、`1h`、または分として扱われる数字だけ）を入力して `Enter` を押すとカウントダウンが始まり、メイン一覧の「Timer」の横にリアルタイムで表示されます（待機中は `Timer: --:--`）。ゼロになると、ポップアップが DVD のスクリーンセーバーのように画面中を跳ね回り、壁に当たるたびにテーマが変わります。止めるには、グローバルホットキーを押すか、ポップアップのどこかをクリックするか、キーボードフォーカスがある間に何かキー（`Escape`、`Tab` など）を押します。鳴る前に気が変わったら、期間の入力中でも、メインの検索で「Timer」を選択している状態でも、`Delete` でカウントダウンを取り消せます。

## Sticky Notes

`"magi:notes"` 項目（下記参照）を追加すると使えるようになります。件数無制限の短いテキストメモ帳で、`apps.json`・`themes.json` の隣の `notes.json` に保存されます。選択するとすべてのメモが一覧表示され（新しいものが先頭、メイン一覧の「Notes」の横にリアルタイムで表示）、Window Switcher とまったく同じようにあいまい検索できます。その中にいる間、検索欄のプレースホルダーは `Type a note...` に変わります。

- 既存のメモに一致する文字を入力して `Enter` で、そのメモをクリップボードにコピーしてランチャーを閉じる
- 何にも一致しない文字を入力して `Enter` で、新しいメモとして追加し、続けて追加できるよう開いたままにする
- `Delete` で選択中のメモを削除、`Shift+Delete` ですべて削除
- `Shift+Enter` で、コピーする代わりに `notes.json` を関連付けられたエディターで直接開く — メモを手で編集するのに便利です（複数行、並べ替えなど）
- 検索欄が空のときの `Tab` / `Escape` / `Backspace` でピッカーを閉じる

最新のメモを消すだけなら、ピッカーを開く必要すらありません。メイン一覧の「Note」項目で直接 `Delete` を押せば、タイマーを入力画面を開かずに取り消すのと同じように消せます。

## Auto-restart

`"magi:auto-restart"` 項目（下記参照）を追加すると使えるようになります。MAGI がバックグラウンドで起動し続ける対象の一覧で（任意の `path`、`apps.json` の項目と同じ形式で引数も可。最初から拒否されるものはありません）、`apps.json`・`themes.json` の隣の `restart.json` に保存されます。専用のスレッドが数秒ごとに、監視中の各対象のプロセスがまだ動いているかを（ハンドルを保持するのではなく実行ファイル名で）確認し、動いていなければすぐに再起動します。クラッシュでも、自分で閉じた場合でも違いはなく、どちらでも戻ってきます。項目を選択すると、現在監視中のすべての対象が一覧表示され（メイン一覧の「Auto-restart」の横に `Auto-restart: N` としてリアルタイム表示、空なら `0`）、Sticky Notes とまったく同じようにあいまい検索でき、それぞれに `★`（実行中）または `☆`（現在は実行されていない）が付きます。その中にいる間、検索欄のプレースホルダーは `Type a target to watch...` に変わります。

- 既存の対象に一致する文字を入力して `Enter` しても何もしません（既存の項目には、下の `Delete` で外す以外にすることがないため）
- 何にも一致しないパスを入力して `Enter` で、監視一覧に追加し、続けて追加できるよう開いたままにする — エクスプローラーのアドレスバーから貼り付けるのとまったく同じように（バックスラッシュは 1 つ）入力してください。この欄は JSON ではなく普通のテキストなので、二重にする必要はありません。後で `restart.json` そのものを開くと見える二重のバックスラッシュは、書き込み時の通常の JSON エスケープにすぎず（`apps.json` の `path` と同じ規則、下記参照）、MAGI はどちらでも正しく読み込みます。
- `Delete` で選択中の対象の監視をやめる（アプリ自体を閉じたり終了させたりは**しません**。監視を終えるだけです）
- `Shift+Delete` ですべての対象の監視を一度にやめる（Sticky Notes と同じく、一覧全体を消去）
- 検索欄が空のときの `Tab` / `Escape` / `Backspace` でピッカーを閉じる

対象が `apps.json` に別途存在している必要はありません。2 つの一覧は完全に独立しているので、同じアプリを通常の起動項目にも、監視される Auto-restart の対象にも、その両方にも、どちらにもしないこともできます。検出は単に「この実行ファイル名が動いているかどうか」だけなので、MAGI は本当のクラッシュと意図的にウィンドウを閉じた場合を区別できません。一覧にあれば、必ず戻ってきます。また、固まっているがまだ動いている（「応答なし」の）対象を検出して強制終了しようともしません。一時的に忙しいだけで、もうすぐ自然に回復するものを終了させてしまう恐れがあり、何もしないより悪いからです。通知領域メニューにも「Disable/Enable Auto-restart」の切り替えがあり、監視一覧そのものには触れずに監視全体を一時停止できます（ホットキーを無効にするのと同じ考え方です）。

## Auto-kill

Auto-restart の鏡像で、同じバックグラウンドスレッドを共有します。`"magi:auto-kill"` 項目で、MAGI が**終了させておく**対象の一覧（`kill.json` に保存）が使えるようになります。数秒ごとに、実行中のものを見つけると終了させます（その実行ファイル名のすべてのインスタンス）。ピッカーは Auto-restart とまったく同じように動作します — メイン一覧に `Auto-kill: N`、あいまい検索可能、各対象に `✖`（実行中、終了される）または `·`（実行されていない）が付きます — プレースホルダーは `Type a target to kill...` です。`Enter` で対象を追加、`Delete` で選択中の対象を外し、`Shift+Delete` で一覧を消去します。

譲れず、設定もできない安全のための 2 つのルール：

- **10 秒の猶予。** Auto-kill を有効にしてから最初の 10 秒間は何も終了されません — 毎回です：MAGI の起動時と、通知領域から有効にするたび。`kill.json` が本当に必要なものを指していたら、最初の終了が起きる前に通知領域を開いて「Disable Auto-kill」を選ぶための時間です。
- **MAGI は自分自身を決して終了させません。** `kill.json` に何が書いてあっても `magi_launcher.exe` は除外されます。そうしないと、誤った一覧とスタートアップ起動が重なったとき、起動のたびに MAGI が終了させられ、無効にするための通知領域アイコンも残らなくなります。

Auto-kill は既定で**無効**です（既定で有効な Auto-restart とは違います）。プロセスを終了させる機能は、意図して有効にするべきだからです。通知領域の切り替えと `state.json` の `auto_kill_enabled` のどちらでも選択が保存され、どちらの方法で有効にし直しても 10 秒の猶予が再び始まります。

## ごみ箱

組み込みの `"magi:empty-recycle-bin"` 項目（下記参照）は、名前の横に項目数とサイズをリアルタイムで表示し、空にした瞬間にすぐ更新されます。直後にランチャーを開き直しても、古い表示が残ることはありません。この項目で `Enter` を押すと、今ごみ箱に実際に入っているものの一覧が、あいまい検索できる形で開きます（すべてのドライブ分を `$Recycle.Bin` から直接読み込みます。UI スレッドの外で読むので、遅い・大きなごみ箱でもランチャーが固まることはありません。エクスプローラーのウィンドウは使いません）：

- 入力して、削除された項目の一覧をあいまい検索で絞り込む（ほかと同じ）
- 選択中の項目で `Enter` を押すと、その完全な名前（拡張子付き）をクリップボードにコピーしてランチャーを閉じる
- `Delete` で、選択中の項目だけをごみ箱から完全に削除 — ほかはそのまま
- `Shift+Delete` で、この画面からもごみ箱全体を空にする — ランチャーは開いたままで、（空になった）一覧がその場で更新されます
- 検索欄が空のときの `Tab` / `Escape` / `Backspace` でメイン一覧に戻る

ごみ箱を開かずに空にするには、メイン一覧の項目で直接 `Shift+Enter` か `Delete` を使います。閲覧画面を開くキーとはあえて別にしてあるので、中身をちょっと見るだけのつもりで誤って空にしてしまうことはありません。どちらの場合もランチャーは開いたままで、項目の横の数だけが更新されます。

## Emoji

`"magi:emoji"` 項目（下記参照）を追加すると使えるようになります。Unicode の公式な絵文字名（"fire"、"red heart"、"grinning face" など）をあいまい検索し、`Enter` で絵文字そのものをクリップボードにコピーしてランチャーを閉じます。絵文字の一覧は同梱されておらず、JSON でもありません。Unicode 自身が [unicode.org/Public/emoji/latest/emoji-test.txt](https://www.unicode.org/Public/emoji/latest/emoji-test.txt) で公開しているテキストの参照ファイル `emoji-test.txt` を、`apps.json`・`themes.json` と同じく実行ファイルの隣に置いて読み込みます。メイン一覧には名前の横に `Emoji: Version 17.0`（またはファイルが宣言するバージョン）がリアルタイムで表示されます。ファイルがない場合は代わりに `Emoji: missing emoji-test.txt` と表示され、`Enter` を押しても何もしません。上のリンクからコピーをダウンロードして `.exe` の隣に置けば（ランチャーがすでに動いているなら、その後 **Reload**）使えるようになります。

- 入力して名前をあいまい検索で絞り込む（ほかと同じ）
- 検索欄が空のときの `Tab` / `Escape` / `Backspace` でメイン一覧に戻る

後で新しい絵文字セットに更新するには、`emoji-test.txt` を Unicode の新しいコピーに置き換えて **Reload** するだけです。再ビルドは不要です。絵文字はシステムの絵文字フォントでカラー表示され、そのフォントはピッカーが開いている間だけ読み込まれます。描けないものは普通のテキストで表示されます：Windows の国旗（絵文字フォントに国旗がないため）や、フォントが追いつくまでの追加されたばかりの絵文字です（コピーはどちらでも動作します）。

## Copy History

既定で有効です。通知領域メニュー（「Enable/Disable Copy History」）で切り替えられ、`"magi:copy-history"` 項目（下記参照）を追加すればランチャーから閲覧できます。有効な間は、システムのどこでコピーしたテキストもすべて記録され、新しいものが先頭になり、メイン一覧の「Copy History」の横に件数として（切り替えが無効の間は `disabled` と）リアルタイムで表示されます。

- 入力して過去のコピーをあいまい検索で絞り込む（ほかと同じ）
- 選択中の項目で `Enter` を押すと、それをクリップボードにコピーし直してランチャーを閉じる — この再コピーで重複した項目は追加されません
- `Delete` で選択中の項目を削除、`Shift+Delete` で履歴をすべて消去
- 検索欄が空のときの `Tab` / `Escape` / `Backspace` でメイン一覧に戻る

**保存場所：** ディスク上のどこにも、決して保存されません。履歴はランチャー自身のプロセスのメモリ（RAM）にだけ保持され、合計 1,000,000 バイトが上限です（いっぱいになると古い項目から削除）。PC の電源を切れば跡形もなく消え、見つかるファイルもテレメトリもありません。各項目のメモリは `VirtualLock`（Linux では `ulimit -l` の範囲内で `mlock`）でロックされ、メモリが逼迫してもシステムがディスクにスワップしないようになっており、手放された瞬間（押し出し、削除、または通知領域から終了したとき）にゼロで上書きされます。コピーした内容をクリップボード履歴から除外するよう指定するパスワードマネージャーは、Windows ではその指定が尊重されます。

これは慎重ではあっても、絶対ではありません。Copy History を開いている間はそのテキストが画面上や UI 自身のメモリにもあり、現在のクリップボードの内容はシステムが保持しており、読み取る際には短時間だけコピーが作られます。あえて**暗号化はしていません**。同じプロセス内にある復号鍵では、すでにプロセスのメモリを読めるものを何も止められないからです。

通知領域の切り替え（`hotkey_enabled`・`auto_restart_enabled`・`auto_kill_enabled`・`copy_history_enabled`）の状態は、切り替えた瞬間に `state.json`（下記参照）に保存されるので、再起動後も保たれます。

## Eject

`"magi:eject"` 項目（下記参照）を追加すると使えるようになります。現在接続されている USB 接続のドライブをすべて、あいまい検索できる一覧で表示します。

- 入力して一覧をあいまい検索で絞り込む（ほかと同じ）
- 選択中のドライブで `Enter` を押すと、*現在何もそれを開いていない場合に限り*取り出します — 成功すると一覧から消え、ランチャーは開いたままなので、複数のドライブを続けて取り出すのにピッカーを開き直す必要はありません。まだ何かがハンドルを開いている場合（スキャン中のウイルス対策やインデクサー、ファイルを開いているアプリなど）、`Enter` は何もせずドライブには触れません — それでも強制する場合は下の `Shift+Delete` を参照
- `Shift+Delete` で、まだ何かが開いていても選択中のドライブを強制的に取り出す — 頼る前に下の注意を読んでください
- 検索欄が空のときの `Tab` / `Escape` / `Backspace` でメイン一覧に戻る

USB バス上のドライブだけを一覧にします（`GetDriveTypeW` のリムーバブル／固定のフラグではなく、デバイスそのものを直接確認します。このフラグは外付けの USB-SATA／UASP ケースの多くを「固定」と誤って報告するためです）。システムドライブや内蔵の 2 台目のドライブは決して表示されません。

まずボリュームをロックしてマウントを解除し（`FSCTL_LOCK_VOLUME`・`FSCTL_DISMOUNT_VOLUME`）、次にプラグ アンド プレイ マネージャーでデバイスを取り外します（`CM_Request_Device_Eject`）。サードパーティの USB 取り出しユーティリティと同じ方法です。要求はドライブそのものではなく、取り外し可能とされた最初の祖先（最悪でも USB ポート）に対して出すので、自分をリムーバブルと報告しない外付けケース — Windows 自身のメニューが表示しない、またはグレーアウトするもの — でも動作します。取り出しはバックグラウンドで行われ、その間もランチャーは操作でき、「Ejecting...」と表示されます。

**`Shift+Delete` は取り出しを強制します — 事前に確認はしません。** 通常の `Enter`（ボリュームのロックが拒否された時点できれいに引き下がります）とは違い、強制の場合はその確認をまるごと飛ばします。別のプロセスがまだドライブ上のファイルを開いていてもマウント解除は成功し、そのプロセスのハンドルは取り出しを妨げることなく単に無効になります（I/O エラーを受け取ります）。バックグラウンドのスキャン（ウイルス対策、検索インデクサー）がこうして*読み込み*中に中断されても害はありません — 何も変更されておらず、相手側でエラーになるだけです。しかし、まさにその瞬間にドライブへ実際に*書き込み*中のファイル（コピーの途中、保存の途中）は、事前の警告なしに途切れたり壊れたりします。「今何かが書き込み中か」の確認は一切なく、強制は強制です。

## Linux

上記はすべて Linux でも動作し、違いは次のとおりです。ファイル形式は同じで、パスは `%VAR%` の代わりに `/` と `$VAR` または `~` を使います。

**X11 と Wayland。** X11 ではすべての機能が使えます。Wayland では、アプリケーションがキーボードをグローバルに監視したり、ほかのウィンドウを見たり、自分の位置を決めたりできないため：

- グローバルホットキーは使えません。代わりに、デスクトップの設定で実行ファイルをショートカットに割り当ててください。動作中にもう一度起動すると、ランチャーの表示／非表示が切り替わります（X11 でも同じです）。
- Window Switcher は空のままです。
- ウィンドウの位置や、タスクバーに表示されるかどうかはコンポジターが決めます。

**必要なもの。** ランチャー自体に必要なのは、ほぼすべてのデスクトップにある fontconfig だけです。下の各ツールは、それを使う機能にだけ必要です：

| 機能 | ツール |
|---|---|
| ドキュメント、フォルダー、アドレスを開く | `xdg-open`（`xdg-utils`） |
| Eject | `lsblk` と `udisksctl`（`udisks2`） |
| メディアキー | `playerctl` |
| 音量キー | `pactl`（PulseAudio または PipeWire） |
| カラー絵文字 | Noto Color Emoji フォント |
| 通知領域アイコン | 通知領域（StatusNotifierItem）のあるデスクトップ。ない場合もランチャーは動作し、プロセスを終了して閉じます |

**そのほかの違い：**

- Copy History は通知を受けるのではなく 1 秒ごとにクリップボードを確認するため、パスワードマネージャーの除外指定は見えず、その 1 秒以内に置き換えられたテキストは記録されません。
- ごみ箱はホームのごみ箱（`~/.local/share/Trash`）です。ディスクごとのごみ箱フォルダーは読み込みません。
- Auto-restart と Auto-kill はプロセスのコマンドラインにあるプログラム名で比較するので、スクリプトはそのインタープリター名（`python3`）で表示されます。
- 時計は常に 24 時間表示です。
- `hidden` は効果がありません：プログラムの出力はもともと表示されないためです。
- `Shift+Enter` は対象を含むフォルダーを開きますが、対象を選択はしません。

## 設定

`apps.json` と `themes.json` は実行ファイルの隣にあり、決して実行ファイルに埋め込まれません。そのため、再ビルドせずに手で編集できます。アプリを再起動せずに変更を反映するには **Reload**（`"magi:reload"` 項目）を使います。

`state.json` もそこにありますが、別の種類のファイルです。内部の記録（現在のテーマ、フォント・ウィンドウ・枠の設定、通知領域の切り替え）で、ランチャー自身が起動時に一度読み込み、キーボード・通知領域・テーマピッカーからそれらを変更した瞬間に自動で書き換えます。下の `notes.json`・`restart.json` と同じ理由で、動作中に手で編集するためのものではありませんが、初回起動前に初期値を設定したい場合や、今保存されている内容を見たいだけの場合は [`state.json`](#statejson) を参照してください。

`notes.json`・`restart.json` もそこにありますが、これらも別の種類のファイルです。`notes.json` は文字列の単純な JSON 配列（`["note 1", "note 2"]`）、`restart.json` は `path` 文字列の単純な JSON 配列（`["A:\\Apps\\Foo\\Foo.exe"]`）で、どちらも Sticky Notes・Auto-restart で項目を追加・削除するたびにアプリ自身が自動で作成・書き換えます。そのため、普段はランチャーのメモリ上のコピーが常に正となります。手で編集するためのものではありませんが、**Reload** はこの 2 つも（`apps.json`・`themes.json`・`state.json` と一緒に）ディスクから読み直すので、どちらかを手で編集しても再起動せずに反映されます。

`emoji-test.txt` はさらに別の種類です。Unicode から取ってきたままのテキストの参照ファイルで（上の [Emoji](#emoji) を参照）、JSON でもなく、MAGI 自身が書き込むものでもありません。更新するにはファイル全体を置き換えるだけで、項目ごとに手で編集するものは何もありません。なくても構いません：ない場合、絵文字ピッカーは使えないままになります（メイン一覧に `Emoji: missing emoji-test.txt` と明示されます）。

実行ファイルの隣の `shortcuts/` フォルダーもなくて構いません。その直下にあるファイル（サブフォルダーは対象外）はすべて起動できる項目になり、検索順位が同じ場合は `apps.json` の項目の後に表示されます。`.lnk`、`.bat`、`.cmd`、`.vbs` など何でもよく、MAGI は拡張子を確認せず、ほかのすべての項目と同じ `ShellExecute` の呼び出しにパスを渡すだけです（この呼び出しは、エクスプローラーでダブルクリックしたときとまったく同じように、`.lnk` を解決したり `.bat`・`.vbs` を実行したりできます）。項目名は拡張子を除いたファイル名です。フォルダーがない、または空の場合は、何の影響もなく、何も追加で表示されません。

### `apps.json`

```json
{
  "apps": [
    { "name": "Notepad", "path": "%windir%\\system32\\notepad.exe" },
    { "name": "Command Prompt", "path": "%windir%\\system32\\cmd.exe", "cwd": "%HOMEDRIVE%%HOMEPATH%" },
    { "name": "Some background script", "path": "A:\\Scripts\\thing.ps1", "hidden": true }
  ]
}
```

- **`name`**（必須） — 表示名。あいまい検索の対象になります。
- **`path`**（必須） — 単純なパス、引数付きのパス（`"app.exe --flag"`）、シェル URI（`ms-settings:...`、`shell:RecycleBinFolder` など）、または下の[特殊な `magi:` 項目](#特殊エントリー)。すべて `ShellExecute` を通るので、エクスプローラーが開けるもの（`.msc` ファイルのように、ファイルの関連付けで解決されるドキュメントの種類も含む）は何でも動作します。`\` は JSON のエスケープ文字なので、バックスラッシュは二重にする必要があります（`"A:\\Apps\\Foo.exe"`）。`\` が 1 つだけだと不正な JSON になり、パスが気付かないうちに壊れることがあります（`\t`、`\n` などは本物のエスケープシーケンスです）。スラッシュ（`"A:/Apps/Foo.exe"`）も使え、エスケープは不要です。Windows はどちらも受け付けます。
- **`cwd`**（任意） — 作業フォルダー。既定では対象自身のフォルダー（エクスプローラーでのダブルクリックと同じ）ですが、`cmd.exe`・`powershell.exe` のような項目では、通常は明示的に指定したくなるでしょう（指定しないと `system32` で起動します）。
- **`hidden`**（任意、既定は `false`） — ウィンドウを表示せずに起動します（`SW_HIDE`）。何も表示するものがないスクリプト向けです。

#### 特殊エントリー

| `path` | 効果 |
|---|---|
| `magi:reload` | `apps.json`・`themes.json`・`state.json`・`notes.json`・`restart.json`・`kill.json`・`emoji-test.txt`・`shortcuts/` をその場で読み直す。再起動は不要 |
| `magi:theme-picker` | テーマをリアルタイムで選ぶピッカーに入る（下記参照） |
| `magi:timer` | タイマーの期間入力に入る。待機中は `<名前>: --:--`、作動後はリアルタイムのカウントダウンを表示 |
| `magi:notes` | Sticky Notes のピッカーに入る（上記参照）。空なら `<名前>:`、そうでなければ `<名前>: <最新のメモ>` を表示 |
| `magi:auto-restart` | Auto-restart のピッカーに入る（上記参照）。監視中の対象の数を `<名前>: N`（空なら `0`）と表示 |
| `magi:auto-kill` | Auto-kill のピッカーに入る（上記参照）。終了対象の数を `<名前>: N`（空なら `0`）と表示 |
| `magi:copy-history` | Copy History のピッカーに入る（上記参照）。保存されている項目数を `<名前>: N` と表示し、通知領域の切り替えが無効の間は `<名前>: disabled`（Enter は何もしない） |
| `magi:open-folder` | MAGI Launcher のあるフォルダーをファイルマネージャーで開く — 起動のたびに解決し直すので、フォルダーを移動しても追従します |
| `magi:empty-recycle-bin` | 空でなければ `<名前>: N items, X MB` を表示。`Enter` で中身を閲覧（上の[ごみ箱](#ごみ箱)を参照）、`Shift+Enter` または `Delete` で空にする |
| `magi:emoji` | 絵文字ピッカーに入る（上記参照）。`emoji-test.txt` から `<名前>: Version X.Y` を表示し、ファイルがなければ `<名前>: missing emoji-test.txt`（Enter は何もしない） |
| `magi:eject` | Eject のピッカーに入る（上記参照） |
| `magi:media-play-pause`、`magi:media-next`、`magi:media-previous`、`magi:media-stop`、`magi:media-volume-mute`、`magi:media-volume-down`、`magi:media-volume-up` | 対応する仮想メディアキーを送る。本物のハードウェアキーと同じように振り分けられます（このウィンドウだけでなく、グローバルなメディアセッション） |

本物の「Windows のシャットダウン」ダイアログ（デスクトップで `Alt+F4` を押したときと同じもの）も、特別なコードなしに通常の項目として追加できます：

```json
{
  "name": "Shutdown",
  "path": "%windir%\\system32\\WindowsPowerShell\\v1.0\\powershell.exe -command \"(New-Object -ComObject Shell.Application).ShutdownWindows()\"",
  "hidden": true
}
```

### `themes.json`

```json
{
  "themes": {
    "arc-dark": {
      "search_background": "#404552",
      "search_text": "#7c818c",
      "list_background": "#383c4a",
      "list_text": "#d3dae3",
      "selected_background": "#5294e2",
      "selected_text": "#ffffff",
      "border": "#4b5162"
    }
  }
}
```

カラーパレットそのものだけです — どれが有効か、そしてほかのすべての表示設定は、代わりに下の [`state.json`](#statejson) にあります（`themes.json` を新しいパレット集にまるごと置き換えても、自分の設定がリセットされないよう分けてあります）。

`themes` 辞書に 100 以上の組み込みテーマ（主にキャラクターやゲームのパレット）を同梱しています。ランチャーを開いて `Themes` 項目（`magi:theme-picker`）を選ぶと、再起動なしでリアルタイムにプレビューしながら切り替えられます。ピッカーは、アルファベット順の最初のテーマではなく、現在有効なテーマの位置で開きます。

### `state.json`

MAGI Launcher が自分で書き込む内部の記録です。触る必要はないはずですが、見たい場合や初回起動前に初期値を設定したい場合のために、ごく普通の JSON になっています：

```json
{
  "ui": {
    "theme": "arc-dark",
    "font_family": null,
    "placeholder_text": "Type to search...",
    "show_clock": true,
    "window_size": 30,
    "border": 1
  },
  "auto_restart_enabled": true,
  "auto_kill_enabled": false,
  "copy_history_enabled": true,
  "hotkey_enabled": true,
  "hotkey": "Ctrl+Space"
}
```

- **`ui.theme`** — `themes.json` の `themes` 辞書で有効な項目の名前。テーマピッカーで選んだ瞬間に書き込まれます。
- **`ui.font_family`** — `null` なら OS の既定のフォントのまま。おすすめのフォント：[SGr-Iosevka-Regular.ttc](https://github.com/be5invis/iosevka)
- **`ui.placeholder_text`** — 検索欄が空のときに表示されます（Timer・Sticky Notes・Auto-restart・Auto-kill ではモード専用のプレースホルダーに置き換わります。上の各セクションを参照）
- **`ui.show_clock`** — 検索欄の横に現在時刻を表示します（Windows ではユーザーの短い時刻形式）
- **`ui.window_size`** — ポップアップが占める画面幅の割合（0〜100）。高さと文字の大きさはそれに合わせて 16:9 の比率を保ち、常にカーソルのあるモニターの中央に置かれ、画面からはみ出さないよう制限されます。上の `Ctrl+1`〜`Ctrl+0` でキーボードからリアルタイムに調整でき、押すたびに新しい値がここに書き戻されます。
- **`ui.border`** — 擬似的な枠の太さ（ピクセル）。これもリアルタイムに調整できます。上の `Ctrl+-`・`Ctrl+=` を参照。
- **`hotkey`** — （Wayland では使えません。[Linux](#linux) を参照）`"ctrl+space"`、`"ctrl+alt+f"`、`"win+e"`、`"f14"` のような指定。`ctrl`／`control`、`alt`、`shift`、`win`／`super`、`space`、`enter`／`return`、`tab`、`esc`／`escape`、`f1`〜`f24`、および 1 文字に対応しています。
- **`hotkey_enabled`** / **`auto_restart_enabled`** / **`auto_kill_enabled`** / **`copy_history_enabled`** — 通知領域メニューの切り替えを反映します。起動時に一度読み込まれ、通知領域から切り替えた瞬間に自動で書き換えられます。`auto_kill_enabled` の既定は `false`（ほかは `true`） — プロセスを終了させる機能は明示的に有効にするものです。（ここでも通知領域からでも）有効にすると、最初の終了の前に 10 秒の猶予が始まります。
