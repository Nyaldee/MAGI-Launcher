# Solar RIP

*[Read in English](README.md) · [Lire en français](README.fr.md) · [日本語で読む](README.jp.md)*

一个用于 `.rip` 格式的小型补丁工具，支持 Windows 和 Linux。它类似 Lunar IPS，但使用 64 位的偏移量和大小，而不是 IPS 的 3 字节字段，因此没有 16 MB 的大小限制。补丁可以双向使用：既能为原始文件打补丁，也能把打过补丁的文件还原为原始文件。任意大小的文件都能一次读写完成，无需载入内存。Linux 上的差异请见 [Linux](#linux)。

## 格式

`.rip` 保存原始文件与修改后文件之间的差异：依次为签名 `RIP`、各条记录，以及两个文件的大小和 CRC32。定长数值均为小端序。

| 字节数 | 内容 |
|---|---|
| 3 | 签名 `RIP` |
| 可变 | 记录 |
| 8 | 原始文件大小 |
| 4 | 原始文件 CRC32 |
| 8 | 修改后文件大小 |
| 4 | 修改后文件 CRC32 |
| 4 | 之前全部内容的 CRC32 |

每条记录依次为：表示与上一条记录末尾距离的数值（第一条从文件开头算起）、表示长度的数值（至少为 1），以及相应长度的字节——即该位置上原始文件与修改后文件的异或（XOR）。这些数值采用 BPS 的变长编码：每字节 7 位，最高位标记最后一个字节，每多一个字节，取值范围就随之平移，因此每个数值只有唯一一种写法。

两个文件都被视为用零填充到较长者的长度。记录之外，两者完全相同；超出较短文件末尾的部分全部包含在记录中。应用补丁时，每条记录在其位置与文件进行异或，从而把其中一个文件变为另一个，再把结果调整为另一个文件的大小。CRC32 与 zip、gzip 使用的相同（IEEE 802.3）。大小和 CRC32 放在最后，是为了让补丁一次写成。

该格式是固定的：只有一个版本，今后不会改变。

## 安全性

补丁同时知道两个文件，因此每次应用都会经过校验：

- **在结果完整并通过校验之前，不会替换任何文件。** 新文件会在所选文件旁一次写成，之后才取代它。任何一步失败时，文件保持不变，临时文件会被删除。
- **已经打过补丁的文件**会被识别出来，并且可以还原为原始文件。
- **两者都不是的文件**会连同其大小和 CRC32 一起提示，只有在确认后才会打补丁（命令行中使用 `--force`）。
- **意外损坏的补丁**会借助补丁自身的 CRC32，在打开时即被拒绝。
- **补丁无法让 Solar RIP 写入超过文件和补丁自身数据的内容**：格式错误或恶意的补丁无法塞满磁盘。
- **Solar RIP 创建的每个补丁在保存前都会经过双向校验**：在不写入任何内容的情况下，它必须能把原始文件精确地变为修改后的文件，并把修改后的文件精确地变回原始文件。

CRC32 防范的是意外——下载损坏、选错文件——而不是篡改：它不是签名，补丁可以被刻意构造成与之匹配。请只应用来自可信来源的补丁。

## 使用方法

- **Apply Patch** — 先选择 `.rip`，再选择要打补丁的文件。结果通过校验后，文件会被原地打补丁（见 [安全性](#安全性)）。如果选择的是已经打过补丁的文件，会询问是否还原为原始文件。
- **Create Patch** — 选择原始文件和修改后的文件，保存生成的 `.rip`。之后程序会关闭。
- **Scramble File** — 保存一份前 4 KB 被替换为噪声的文件副本，以及能将其还原的 `.rip`。原文件永远不会被修改。
- **Verify Patch** — 显示 `.rip` 期望的原始文件和修改后文件（CRC32 与大小）以及记录数，不会改动任何文件。
- **Register** — 将 `.rip` 文件关联到此程序（按用户设置，无需管理员权限）。之后双击 `.rip` 会直接进入选择要打补丁的文件，即使 Solar RIP 已经打开。如果程序被移动，会重新显示 OFF：点击即可更新关联。
- **Create Log** — 切换是否在打好补丁的文件（Apply Patch）或补丁（Create Patch、Scramble File）旁写入 `.log` 文件。
- **Exit**
- **Website** — 打开 nyaruhodo.com。

在消息中，Enter 确认，Escape 取消。同一时间只运行一个主窗口——再次启动会把第一个窗口带到前台。

## 命令行

同样的操作可以不打开窗口，在脚本中运行：

```
solar_rip apply <patch.rip> <文件> [--force] [--log]
solar_rip restore <patch.rip> <文件> [--log]
solar_rip create <原始文件> <修改后的文件> <patch.rip> [--log]
solar_rip scramble <文件> <加扰后的文件> <patch.rip> [--log]
solar_rip verify <patch.rip>
solar_rip --help
```

- `apply` 原地为文件打补丁。如果文件已经打过补丁，或者不是补丁期望的原始文件，就会停止（后一种情况可用 `--force` 继续）。
- `restore` 将打过补丁的文件原地还原为原始文件。
- `--log` 写入与 **Create Log** 相同的 `.log` 文件。
- 退出码：成功为 `0`，操作失败为 `1`，命令格式错误为 `2`。错误信息写入错误输出。

Solar RIP 是带窗口的程序，因此在 Windows 的交互式命令提示符中，系统不会等待它结束，结果会显示在下一个提示符之后。脚本（`.bat`、PowerShell）会等待它结束，并取得输出和退出码；在交互式 `cmd` 中，请使用 `start /wait /b solar_rip …`。

## Linux

以上所有功能在 Linux 上同样可用，区别如下：

- **文件对话框**通过 XDG 门户（`xdg-desktop-portal`，GNOME、KDE 及大多数桌面都已附带）由桌面提供，外观与系统其他部分一致。
- **Register** 会在 `~/.local/share` 下写入 `*.rip` 的 MIME 类型、一个隐藏的应用程序条目及其图标，并在已安装时运行 `update-mime-database`、`update-desktop-database` 和 `xdg-mime`（`shared-mime-info`、`desktop-file-utils`、`xdg-utils`）。不会向应用程序菜单添加任何内容。
- **Website** 使用 `xdg-open`（`xdg-utils`）打开网址。
- **Wayland** 不允许应用程序自行放置窗口或把自己带到前台：Solar RIP 在哪里打开由合成器决定，再次启动时也不会把第一个窗口带到前台。
