# Solar RIP

*[Read in English](README.md) · [Lire en français](README.fr.md) · [阅读中文版](README.zh-CN.md)*

Windows と Linux 向けの、`.rip` 形式用の小さなパッチャーです。Lunar IPS に似ていますが、IPS の 3 バイトのフィールドの代わりに 64 ビットのオフセットとサイズを使うため、16 MB のサイズ制限がありません。パッチは双方向に使えます。元のファイルにパッチを当てることも、パッチ済みのファイルを元に戻すこともできます。どんなサイズのファイルも、メモリに読み込むことなく一度の読み書きで処理されます。Linux での違いは [Linux](#linux) をご覧ください。

## 形式

`.rip` は元のファイルと変更後のファイルの差分を保持します。`RIP` シグネチャ、レコード、そして両方のファイルのサイズと CRC32 の順で構成されます。固定長の数値はリトルエンディアンです。

| バイト数 | 内容 |
|---|---|
| 3 | シグネチャ `RIP` |
| 可変 | レコード |
| 8 | 元のファイルのサイズ |
| 4 | 元のファイルの CRC32 |
| 8 | 変更後のファイルのサイズ |
| 4 | 変更後のファイルの CRC32 |
| 4 | それより前のすべての CRC32 |

各レコードは、直前のレコードの末尾からの距離（最初のレコードはファイルの先頭から）を表す数値、長さ（1 以上）を表す数値、そしてその長さ分のバイト（その位置での元のファイルと変更後のファイルの XOR）で構成されます。これらの数値は BPS の可変長エンコーディングを使います。1 バイトあたり 7 ビットで、最上位ビットが最後のバイトを示し、バイトが増えるごとに値の範囲がずれるため、どの数値も書き方は一通りしかありません。

両方のファイルは、長い方の長さまでゼロで埋められたものとして扱われます。レコードの外では両者は同一で、短い方の末尾を超える部分はすべてレコードに含まれます。パッチを当てると、各レコードがその位置でファイルに XOR され、一方のファイルがもう一方に変わり、結果はもう一方のファイルのサイズに合わせられます。CRC32 は zip や gzip と同じもの（IEEE 802.3）です。サイズと CRC32 が最後にあるのは、パッチを一度の書き込みで作れるようにするためです。

この形式は固定されています。バージョンは一つだけで、今後変わることはありません。

## 安全性

パッチは両方のファイルを知っているため、適用のたびに検証が行われます。

- **結果が完成して検証されるまで、何も置き換えられません。** 新しいファイルは選んだファイルの隣に一度の書き込みで作られ、その後で初めて置き換わります。途中で失敗した場合、ファイルはそのまま残り、一時ファイルは削除されます。
- **すでにパッチ済みのファイル**はそのように認識され、元のファイルに戻すことができます。
- **どちらのファイルでもないファイル**は、そのサイズと CRC32 とともに通知され、確認した場合にのみパッチされます（コマンドラインでは `--force`）。
- **偶然破損したパッチ**は、パッチ自身の CRC32 によって、開いた時点で拒否されます。
- **パッチによって Solar RIP が書き込むのは、ファイルとパッチ自身のデータの範囲までです**。不正な形式や悪意のあるパッチでディスクを埋め尽くすことはできません。
- **Solar RIP が作成するパッチは、保存前に双方向で検証されます**。何も書き込まずに、元のファイルを変更後のファイルに、変更後のファイルを元のファイルに、それぞれ完全に一致する形で変えられることを確認します。

CRC32 が防ぐのは事故（破損したダウンロード、間違ったファイル）であり、改ざんではありません。署名ではないため、CRC32 が一致するようにパッチを作ることもできます。信頼できる入手先のパッチだけを適用してください。

## 使い方

- **Apply Patch** — `.rip` を選び、次にパッチを当てるファイルを選びます。結果が検証された後、ファイルはその場でパッチされます（[安全性](#安全性) を参照）。すでにパッチ済みのファイルを選ぶと、元のファイルに戻すかどうかを尋ねます。
- **Create Patch** — 元のファイルと変更後のファイルを選び、作成された `.rip` を保存します。その後アプリは終了します。
- **Scramble File** — 先頭 4 KB をノイズに置き換えたファイルのコピーと、それを元に戻す `.rip` を保存します。元のファイルが変更されることはありません。
- **Verify Patch** — `.rip` が想定する元のファイルと変更後のファイル（CRC32 とサイズ）、およびレコード数を、どのファイルにも触れずに表示します。
- **Register** — `.rip` ファイルをこの実行ファイルに関連付けます（ユーザー単位、管理者権限不要）。以後 `.rip` をダブルクリックすると、Solar RIP が開いていても、パッチを当てるファイルの選択から直接始まります。実行ファイルを移動すると再び OFF と表示されます。クリックすると関連付けが更新されます。
- **Create Log** — パッチ済みのファイル（Apply Patch）またはパッチ（Create Patch、Scramble File）の隣に `.log` ファイルを書き出すかどうかを切り替えます。
- **Exit**
- **Website** — nyaruhodo.com を開きます。

メッセージでは Enter で確定、Escape でキャンセルします。メインウィンドウは一度に一つだけ動作し、二つ目を起動すると最初のウィンドウが前面に表示されます。

## コマンドライン

同じ操作をウィンドウなしで、スクリプトから実行できます。

```
solar_rip apply <patch.rip> <ファイル> [--force] [--log]
solar_rip restore <patch.rip> <ファイル> [--log]
solar_rip create <元のファイル> <変更後のファイル> <patch.rip> [--log]
solar_rip scramble <ファイル> <スクランブル後のファイル> <patch.rip> [--log]
solar_rip verify <patch.rip>
solar_rip --help
```

- `apply` はファイルをその場でパッチします。ファイルがすでにパッチ済みの場合、またはパッチが想定する元のファイルではない場合は停止します（後者は `--force` で続行できます）。
- `restore` はパッチ済みのファイルをその場で元のファイルに戻します。
- `--log` は **Create Log** と同じ `.log` ファイルを書き出します。
- 終了コード：成功時は `0`、操作に失敗した場合は `1`、コマンドの形式が正しくない場合は `2`。エラーはエラー出力に書き出されます。

Solar RIP はウィンドウを持つプログラムのため、Windows の対話的なプロンプトは終了を待たず、結果は次のプロンプトの後に表示されます。スクリプト（`.bat`、PowerShell）は終了を待ち、出力と終了コードを受け取ります。対話的な `cmd` では `start /wait /b solar_rip …` を使ってください。

## Linux

上記のすべては Linux でも動作しますが、次の点が異なります。

- **ファイルダイアログ**は XDG ポータル（`xdg-desktop-portal`、GNOME、KDE、およびほとんどのデスクトップに付属）を通じてデスクトップから提供されるため、システムの他の部分と同じ見た目になります。
- **Register** は `*.rip` の MIME タイプ、非表示のアプリケーションエントリ、そのアイコンを `~/.local/share` に書き込み、インストールされていれば `update-mime-database`、`update-desktop-database`、`xdg-mime` を実行します（`shared-mime-info`、`desktop-file-utils`、`xdg-utils`）。アプリケーションメニューには何も追加されません。
- **Website** は `xdg-open`（`xdg-utils`）でアドレスを開きます。
- **Wayland** では、アプリケーションが自分のウィンドウを配置したり前面に出したりできません。Solar RIP がどこに開くかはコンポジターが決め、二度目に起動しても最初のウィンドウは前面に出ません。
